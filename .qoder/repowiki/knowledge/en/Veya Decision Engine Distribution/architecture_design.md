The root is a flat setuptools distribution (`pyproject.toml`) whose `packages = ["veya", "veya.experimental", "web"]` entry wires three runtime children together: `veya_core` (the `veya` package exposing `Router`, `Agent`, and typed-question primitives), `web_server` (the `web` package serving the UI and proxying to an audited model service), and `veya.experimental` (held-out research components). `data_artifacts/` holds the frozen Hugging Face checkpoints and calibration metadata referenced at runtime by both `veya_core` and `web_server`; `research/` consumes those artifacts to produce benchmark JSONs; `docs_assets/` supplies audit/commercialization reports and the Kaggle fine-tuning notebook consumed by `research`; `tests/` exercises all four code children via pytest plus a Node.js client. There is no cross-child import graph beyond the `veya`/`web` packages — communication between core, server, and research happens through the shared artifact layout on disk and the typed question schema defined in `veya_core`.
