Flat collection of independent test modules under `tests/`, each named `test_<feature>.py` and importing from the top-level `veya` package. Two categories coexist:
- Unit / integration tests run through pytest (`test_phase10_retriever.py`, `test_criteria.py`, `test_manifest.py`, `test_server_security.py`, etc.), often spinning up an in-process `veya.server.serve()` or constructing fake agents.
- Long-running end-to-end scripts that are also pytest-importable but skip themselves unless executed directly as `__main__` (`test_local_e2e.py`, `test_model_server_e2e.py`), which load real production checkpoints from `~/veya_models` or `models/production` and exercise the HTTP `/v1/choice`, `/v1/systemone`, `/health`, `/version` endpoints over a spawned subprocess.
- A single Node.js test file (`test_model_client.mjs`) using `node:test` to validate the browser-side `web/static/model-client.mjs` against a mock fetch; `test_site_content.mjs` validates static site content and navigation.
Dependency direction is one-way: tests import `veya.*` (router, server, release_bundle, lang, domain_retriever) and never the reverse; fixtures are local helper functions/classes rather than shared conftest modules.
