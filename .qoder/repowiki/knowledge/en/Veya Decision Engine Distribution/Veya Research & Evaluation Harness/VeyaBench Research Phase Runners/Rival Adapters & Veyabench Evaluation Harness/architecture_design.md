Two cooperating layers under `research/veyabench/`:

- Rival adapter layer (`rivals/`). `base.py` defines the abstract `Rival` interface with a uniform `score(cases, gold)` contract that returns `(rows, seconds)` where each row is `(gold_idx, probs_vector|None)`, plus helpers `option_labels`, `option_texts`, `probs_from_scores`, `render_state`, and `to_rows`. Concrete rivals in `jev.py` (Jev/TypeSafe System One), `nli.py` (BART-MNLI zero-shot via `transformers.pipeline`), and `st.py` (sentence-transformers nearest-centroid) subclass `Rival` and implement `_options_probs(state, qdef, options)`. Each rival lazily imports its heavy dependency inside `_ensure()` / `_options_probs` and advertises availability through `available()` + `unavailable_reason()`. `__init__.py` exposes a `REGISTRY = {"nli": ..., "st": ..., "jev": ...}` for dynamic selection.
- Evaluation harness layer: loose `run_*.py` scripts are one-shot entry points that load frozen release manifests, drive `veya.release_bundle.load_release_manifest`, and write aggregate JSON artifacts. `protocol.py` provides shared utilities — `SplitLedger` (enforces disjoint train/calibration/validation/test splits with `LeakError`), `recall_at_k`, `mine_hard_negatives`, `complement_error`, `permutation_report`, and `risk_coverage` (with SAC curves). `write_baseline.py` produces the post-fix baseline artifact from the local English checkpoint.

Dependency direction is one-way: runners import `veya.*` and `veyabench.rivals`; rivals never import runners; `protocol.py` has no runner dependencies.
